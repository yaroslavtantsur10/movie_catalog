# Лабораторна робота №1

## Тема
Основи мови програмування Dart.

## Варіант 2 — Каталог фільмів

Консольна програма для обробки каталогу фільмів.

## Можливості програми

- Обробка 15 записів про фільми.
- Перевірка коректності даних.
- Використання записів (records) та typedef.
- Фільтрація фільмів за рейтингом.
- Обчислення середнього рейтингу.
- Підрахунок загальної тривалості.
- Групування фільмів за жанрами.
- Сортування за рейтингом та роком.
- Обчислення віку фільмів через DateTime і Duration.
- Робота з регулярними виразами.
- Використання замикань (closures).
- Формування звіту через StringBuffer.

## Структура проєкту

- `bin/movie_catalog.dart` — головна програма.
- `lib/movie_catalog.dart` — функції обробки фільмів.
- `test/movie_catalog_test.dart` — автоматичні тести.

## Запуск

```bash
dart pub get
dart run
```

## Перевірка

```bash
dart format .
dart analyze
dart test
```

## Результат

З 15 записів:
- 12 коректних;
- 3 помилкових.

Середній рейтинг: 8.43.
Загальна тривалість: 1672 хвилини.

## Чому я так зробив програму

Я розділив програму на три файли, щоб не писати весь код в одному місці. У `bin` знаходиться запуск програми, у `lib` — основні функції, а в `test` — перевірка їх роботи. Так мені простіше розбиратися в коді та виправляти помилки.

Для одного фільму я використав `record` і `typedef Movie`, тому що у кожного фільму однакові поля: назва, режисер, рік, тривалість, жанр і рейтинг. Можна було створити окремий клас, але для цієї роботи `record` простіший.

Початкові дані зберігаються у `List<String>`, оскільки їх потрібно спочатку розібрати та перевірити. Після перевірки використовується `List<Movie>`. Для групування за жанрами я використав `Map<String, List<Movie>>`, щоб для кожного жанру отримати список його фільмів.

## Залежності

У проєкті використовуються пакети `test` і `lints` з pub.dev.

`test` потрібен для автоматичних тестів. Він дозволяє перевіряти результат роботи функцій через `expect()`. Можна було перевіряти все вручну або через `assert()`, але з `test` зручніше бачити, яка саме перевірка не пройшла.

`lints` потрібен для перевірки стилю коду. Він містить готові рекомендації для Dart, які підключаються через `analysis_options.yaml`. Замість цього можна було налаштувати правила самому, але для лабораторної мені вистачило стандартних.

Обидва пакети використовуються під час розробки. Для самої роботи з фільмами додаткові бібліотеки не потрібні.

## Інші варіанти реалізації

Замість `where`, `map` і `fold` можна було використовувати звичайні цикли `for`. Я використав методи колекцій, тому що так зручніше виконувати фільтрацію та підрахунки.

Для формування звіту можна було просто додавати рядки через `+`, але я використав `StringBuffer`, тому що звіт складається з декількох рядків.
